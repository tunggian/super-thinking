# Path Dependence（路径依赖）

## R — 原文 (Reading)
> 路径依赖意味着你现在可用的决策集合（路径）取决于你过去的决策。有时一个初始决策或事件看似无害，但它会深刻影响或限制你长期的可能结果。

## I — 方法论骨架 (Interpretation)
路径依赖描述了"历史选择锁定了未来可能性"的机制。核心洞察：决策不是在空白画布上进行的——每个过去的决策都会改变未来可选路径的集合，有时会创造不可逆的"锁定效应"。

书中关键案例：
- **小公司选项目管理软件**：当初没多想选了某个工具 → 公司发展壮大后数据都在里面 → 迁移成本巨大 → 被锁定在次优方案。
- **毕业留城的惯性**：在哪里上学 → 大概率在附近工作 → 影响一生的职业和家庭选择。
- **产业聚集效应**：同类店铺扎堆（珠宝街、家具城、4S店一条街），第一家店铺的位置创建了所有后来者的路径依赖。

路径依赖与技术债务的关系：短期主义产生技术债务，技术债务累积加强路径依赖——"我们欠了太多债，换方案的成本太高了，只能继续用这个"。这是一种自我强化的锁定效应。

关键启示：在早期做决策时要特别审慎，因为初始选择具有不成比例的影响力。Q键盘（QWERTY键盘布局）是经典的路径依赖案例——这个布局最初是为了防止打字机卡键而设计的，虽然现代键盘不需要这个约束，但所有人都已经被锁定。

## A1 — 书中的应用 (Past Application)
1. **小公司软件选型的锁定效应**：小公司随意选择项目管理软件 → 公司发展后所有人都在用 → 数据全在里面 → 切换成本极高 → 即使后来发现软件不够好也难以更换。

2. **大学毕业生的地理锁定**：多数人留在上学城市附近工作 → 这决定了他们可用的职业和家庭选择范围 → 初始的"选学校"决策产生了远超预期的长期影响。

## A2 — 触发场景 (Future Trigger) ★
1. 技术栈选型时——选择React还是Vue？选择PostgreSQL还是MySQL？这些选择将在未来5年锁定团队的招聘、社区支持、工具生态。
2. 首份工作的行业选择——第一份工作所在的行业决定了你的人脉、经验标签和后续跳槽的可选路径。

语言信号: "当初选了XX，现在只能..."、"换的成本太高了"、"大家都在用这个"、"改不了了"

## E — 可执行步骤 (Execution)
1. **识别"可逆/不可逆"属性** - 做决策时先问：这个选择有多少"不可逆"成分？如果选错了，转换成本是多少？使用亚马逊CEO Bezos的"单向门 vs 双向门"框架区分。
2. **保留升级路径** - 即使选择了一个方案，也保持接口抽象/数据可导出，确保未来如果有更好的方案可以迁移（如选择云服务时偏好开放标准）。
3. **定期重新评估锁定成本** - 每半年问一次："如果我们今天重新选择，还会选同样的吗？如果不是，转换的净收益是多少？"

## B — 边界 (Boundary) ★
- 并非所有的路径依赖都是坏事——标准化的锁定（如QWERTY键盘）降低了全社会成本
- 过度恐惧路径依赖可能导致"永远不决策"的瘫痪
- 有些路径依赖是效率的选择（如产业链聚集），而非需要"克服"的问题
